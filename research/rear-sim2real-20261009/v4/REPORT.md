# v4：真实制造商接口的软件接入

当前默认 `bundle-deploy-v9.json`。权重、参考、归一化、控制核心和共享会话状态机不变。

已实际取得并核查制造商项目与 CoRobot 0.2.2 / Forge core 0.43.0；源码、包、原始日志和详细现场指南留在隔离私有交付目录，没有公开内部资料。

选定同机执行路径：Forge 扩展启动现有 ArtGym 控制器；Wuji 保留直接 SDK 30Hz 观测、成功发送目标和历史；独立 CoRobot 进程完成右臂有界轨迹、编码器/重力到位检查及持续单点保活。只发右臂，不填充未知左右手、躯干或左臂目标。后段每周期检查真实来源的 G2 缓存反馈，过期或偏离即拒绝继续。

`require_g2()` 已接入实际桥接入口；它核验桥接源码 pin，桥接再核验实际包、机型/零位/安装/模式/控制权证据、系统模式和新帧反馈。离线回环输入被明确拒绝用于非 fixture 真机会话，没有 `ready=true` 或空后端。

GDT 的真实 PolicyServer RPC 已查明并用实际包验证；本轮服务仅提供状态查询，`reset` 拒绝、返回值没有电机动作字段。选定控制路径要求远端为 `remote_env`，受载期间不切换到 PolicyTaskServer。GDT UI 的启动/复位行为及客户端执行端没有现场验证，不能把状态服务称为 GDT 动作部署已完成。

现有构造函数隐式配置/启动模式的路径已避开：只读连接不自动初始化，模式变更单独在空手授权阶段执行。持刀历史、预载目标和 probe 后卸载→30mm复位→重新摆刀→新历史→完整推动继续沿用 v3。

验证见 `VERIFICATION.json`：380帧合法输入的目标仍为0rad差异，24项既有合同通过；实际制造商客户端/序列化/注册器/PolicyServer通过回环协议合同，最终组合SDK fixture会话1175帧完整结束（21项协议合同通过，p95 8.865ms / max 13.632ms，零超33.33ms）。时序是开发机软件测量，不是现场时延；回环右臂反馈没有接触物理，也不是真机SDK联调结果。

没有新增物理动作或控制插值：手的核心和已发指令保持一致，复用v3的32.420mm、1.033秒有限执行器全段，以及原延迟/刚度失败；不重复仿真、训练或矩阵。

剩余现场事实集中在：确切本体/固件与模型/零位/安装对应；实际只读状态与网络地址；Wuji USB 和右臂独占控制、点动作保活过期行为。现有网络示例不能证明现场电脑能独占手USB。无法释放时须取得相应执行端的具体资料后调整选定路径，不能同时启动两个手写端。

真实机器人未运行，`hardware_deployment_complete=false`。私有指南提供了实际已验证的服务/读取/配置/阶段命令；公开指南只保留可公开内容。

控制器重力输入继续使用保存的固定腕姿先验；新的G2实读FK单独检查其与先验的偏差并记录。≤0.03rad是字段工程门槛，不将该先验标成实机测量；现场必须核实安装/固定链，不能用假反馈越过门槛。

最终恢复工具仅增加显式bundle路径，打包工具增加v4选择及本地hash检查；它们不改变控制核心。原测试bundle/source记录保留，当前501项依赖与控制/权重未变证明见FINAL-PINS.json，未把旧时序回执改写成新bundle。
